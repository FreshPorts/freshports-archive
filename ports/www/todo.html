FreshPorts2 - list of things to do. These items are rather small and modular. Pretty much self-contained. If you're keen to try some of this stuff, join the develop mailing list and put your hand up. Details at http://fp2.unixathome.org/.

  • allow http://freshports.org/www/apache13 to get to the right page (mostly php, some html)
  • take the output of pkg_info and add that to the person's watch list. Ideally, this would work from the command line with the person merely posting the file or something. I don't want to do this with copy/paste. Something which would work entirely from the browser is ideal. (probably a shell script, perhaps some HTML or php or perl)
  • send notices to each person when something on their watch list changes (perl script with some database code?)
  • write a simple little script which compares the contents of the website with what came in on the mail. This is a check to verify that all messages have been received and processed. This script would be run at multiple locations around the world, just to make sure we don't miss anything. It would also entail writing a special URL for the script to use which would allow the script to access messages as it needs to.
  • When an email notification bounces back to us, we need some way of [at least partially] automating the removal of someone from the notification list. In effect we do this: 
          set emailbouncecount = emailbouncecount+1 where email = '<bounced addresss>';
    My guess is that we collect the bounces, parse them for the original address, then plop them into a web page where we can verify what's been done and set that person's bounce count accordingly. An admin would then come along verify what's there, and click YES, do it.
  • Fix the orphaned elements which don't live under the /ports tree when they should. Here's a short example:
